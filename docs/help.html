KiPI User Guide

How to set up, solve and read power integrity simulations of a KiCad board. Every section below can be opened and closed; use the contents on the left to jump around.

Tip: almost every button, box and table in KiPI has a tooltip. Hover over it for a one-line reminder of what it does. Press F1 in KiPI to open this guide.

What KiPI does

KiPI is a power integrity (PI) analyzer that runs as a KiCad 9/10 plugin. It reads the copper of your board straight from the PCB editor and simulates how power gets from your regulators to the parts that use it. It has two analysis modes, chosen at the right end of the toolbar:

ModeQuestion it answersWhat you get
DCWith every load drawing its current, what voltage actually reaches each pin, how much current flows through each trace, plane and via, and how hot does the board get?IR drop and PASS/FAIL per load, voltage, current density, power density, via current and temperature maps in 3D, VRM and loss tables, an optional HTML report.
ACLooking into a device's power pins, how does the impedance of the power distribution network (planes, vias, decoupling capacitors) vary with frequency, and is it below the device's target impedance?|Z| versus frequency curves for each probe point, a cursor to read values off them, and PASS/FAIL against a flat or custom target mask.

KiPI infers nothing about your power system from the schematic. You tell it where the regulators are, what each load draws, which parts sit in series between nets, and (for AC) which capacitor model each decoupling capacitor uses. The board's copper, layer stackup, vias and pads come from KiCad.

Accuracy: KiPI's solvers are a 2.5D finite element model of the copper, checked against closed-form results. Solving the field is the well-understood part; the modelling of vias, regulators and parts is where the approximations are. Treat the results as an engineering estimate and sanity-check anything surprising.

Quick start

DC voltage drop in ten minutes the most common first run
  1. In KiCad, enable Preferences → Plugins → Enable KiCad API (once).
  2. Open your board in the PCB editor and click the KiPI toolbar button. KiPI reads the board (refilling zones first) and draws it in 3D.
  3. In the Nets list on the left, tick the power and ground nets you want to analyze. KiPI pre-ticks a guess the first time.
  4. In the PI setup panel on the right, VRMs tab: click Add, pick the regulator's output net and part, set its voltage. Add its Ground pins if you want the ground return solved too.
  5. Loads tab: click Add for each part that draws current, pick its supply pins, enter its current and a tolerance (e.g. ±3 %).
  6. If a sense resistor, ferrite, fuse or load switch sits between two nets you ticked, add it on the Series links tab.
  7. Click Solve all. Watch the log at the bottom.
  8. Read the Loads table for PASS/FAIL, and click around the 3D view to probe voltages. Switch the field to Current density and tick Arrows to find bottlenecks.

The setup is saved next to your board as <board>.kipi-setup.json every time you solve, so the next session starts where you left off.

AC impedance of one rail after the DC setup has a VRM on the rail
  1. Switch Mode (right end of the toolbar) to AC. The setup panel becomes the AC setup; VRMs and series links are shared with DC.
  2. Make sure the rail's net, its ground and every net its capacitors connect to are ticked in the Nets list.
  3. Capacitors tab: click Models from values to make one model per capacitor value, then enter each model's ESL and ESR from the datasheet (and check the capacitance).
  4. Probes tab: click Add. KiPI picks the busiest part on the rail that also has ground pins, which is usually the load. Set a target impedance, or open the target calculator.
  5. Under the tabs, choose the Rail (by its VRM) and Ground, then click Solve rail.
  6. The Impedance tab in the middle shows |Z| against frequency. Click a curve to place a cursor and read the values in the Info box.
Try it without a board of your own

The repository includes an example: a 4-phase 12 V → 0.9 V, 40 A core rail with decoupling and probes already set up. From a development checkout run

python -m kipi --snapshot examples/multiphase_buck/multiphase_buck.kipi.json.gz

or click Open snapshot… in KiPI and choose that file.

DC concepts

Net groups, the power tree and voltage references

Net groups

KiPI solves copper one net group at a time. A group is a net plus every net joined to it by a series link. For example, +3V3 and +3V3_FILT joined by a ferrite bead are one group. Each group may be driven by at most one VRM. Ground nets used by VRM or load ground pins are their own groups.

The power tree

A VRM's input pins make it a load on its upstream net. KiPI solves the tree from the leaves back to the source: downstream rails first, then each VRM's input current (from its output current, efficiency or quiescent current) is applied as a load upstream. So the 12 V input rail carries the current of everything it feeds.

Voltage reference

Voltages are measured against the source's ground (0 V). If ground pins are given, the ground return is solved too and a load's ground rises above 0 V. The figure to compare with the set point is the load's effective voltage: supply minus ground at the load.

Drop and boost

A drop is a pin below the VRM's set voltage. A boost is a pin above it, which happens with remote sense: the VRM raises its output to hold a sense point further down the copper, so pins nearer the VRM sit above the set point. A load is judged by its worst pin, whichever direction.

The pin picker used everywhere pins are chosen

Every "pins" field is three boxes:

  1. Net: one of the nets ticked in the Board panel. Type to search.
  2. Part: the parts with pads on that net, busiest first, shown as reference, value and pad count, e.g. U4 TPS62130 (3). Type to search (u4 is enough).
  3. Pins: optional pin numbers, comma-separated, e.g. 1,2,5. Blank means every pin of that part on that net; the placeholder lists them.

Optional pickers have (none) as their first net.

Pre-filled fields guesses from the board, always yours to change

As you pick pins, KiPI fills in the fields that usually follow from them. Each guess only fills a field you have not set yourself (an empty field, or one it filled in for the previous part), and when the board does not give an answer the field is left as it was. Change anything it fills in: your value is kept.

How the ground net is found. Ground nets are not always called GND, so KiPI tries, in order: ground nets the setup already uses (any VRM, load or probe ground pins), nets named like a ground (GND, PGND, AGND, VSS, EARTH…), then the board's biggest net (the one with the most pads) if it is not named like a rail. Only nets ticked in the Board panel are used, except grounds the setup already uses. Once one VRM or load has ground pins on an unusually named ground, every later guess uses it.

Series links tab parts between two nets

Sense resistors, ferrite beads, fuses, load switches, 0 Ω links: any part that passes DC from one net to another. Give the part's Side A pins and Side B pins and its Resistance (DCR); 0 is a short. Solve tab choose which net groups to solve

Lists every net group with its role (rail from a VRM, ground, or not driven). Untick groups that are not modeled or routed yet; All and None tick or untick them all. Only ticked groups are validated and solved, and the choice is saved. Where a solved group meets an excluded one:

  • A VRM whose output is excluded becomes a constant load on its input pins, drawing the input current its rail would need at nominal voltages.
  • A VRM whose input is excluded is treated as an ideal source.
  • Ground pins on an excluded ground are ignored.

The Notes results tab lists what was left out and substituted. The Solve button shows how many groups will be solved, e.g. Solve 3 of 5 net groups.

Solving

Solve all, HTML report and Cancel

Solve all saves the setup, meshes every ticked net group and solves the power tree. It is disabled while there are problems (listed in red). If you click it while the 3D view is still building nets, the solve is queued and starts as soon as that finishes.

Tick HTML report before solving to also write <board>_kipi_report.html next to the board; Report opens it. The report is a single offline file with every table, an interactive 3D view of each net group, per-layer statistics and maps, and the temperature map.

A solve that fails on a setup problem (e.g. no copper path) shows Cannot solve in the Notes tab with the reason. Untick the group with the problem in the Solve tab to solve the rest.

Reading the numbers
  • Effective voltage is what the load actually sees: its supply pins minus its ground pins. Compare it with the set point, not the raw plane voltage.
  • A supply plane reading above its set point is normal with remote sense or when ground return is solved; see drop and boost.
  • Worst pin is the one furthest from the set point; with many pins, one far pin can fail a load whose average looks fine.
  • The color scale covers the shown layers only; untick layers to stretch it.
  • Losses are I²R in the copper; VRM conversion loss is the difference between input and output power.

AC concepts

What the AC analysis models

The AC analysis computes the PDN impedance seen from a probe, a device's supply and ground pins, looking out into the board over a range of frequencies. A device that draws a changing current I from a PDN of impedance Z sees its supply move by about I·|Z|, so keeping |Z| below a target impedance keeps the supply ripple within tolerance.

A solve covers one rail (the nets its VRM drives, plus nets joined to them by series links) against one ground net. It includes:

  • The copper, field-solved: plane and trace resistance (with skin effect), the spreading inductance of planes, the capacitance between facing rail and ground copper, cavity resonances, and the inductance of vias and their mounting.
  • Capacitors between the rail and ground, each as a series R-L-C from its model. Only the part's own ESL is entered; its mounting (pads, vias, planes) is simulated.
  • Series links as their resistance plus ESL.
Note: the VRM itself is not modeled as an impedance. In AC, VRMs only define which nets make up a rail and its default ground. Below the frequency where the capacitors take over, the real PDN impedance is set by the regulator's control loop, which the plotted curve does not include: expect the curve to rise toward low frequency as the bulk capacitance runs out.

Capacitors that sit between the rail and ground but have no model are left out, and the results notes list them.

AC setup tabs

Switch Mode to AC. The setup dock becomes the AC setup; it edits the same setup file as DC.

VRMs and Series links tabs shared with DC

The same VRMs and series links as the DC setup; edits in one mode show in the other. Fields that only DC uses are grayed out (their tooltip says so). In AC:

  • A VRM's output net (and ground pins) define a rail and its default ground for the Rail picker.
  • A series link adds its ESL to its resistance. A link leading off the rail to a net that is not part of the solve is left out, with a note. A 0 Ω link with no ESL merges the two nets.

A rail can have several probes, e.g. one per device; they are all solved together and each sees the others as open circuits.

Target Impedance/Frequency Calculator

Works out a flat target from the device's transient spec:

  • AC voltage tolerance: how far the supply may move during a load transient, e.g. the AC part of a ±3 % spec on a 0.9 V rail: 27 mV.
  • Load step (ΔI): the size of the current step.
  • Load step slew rate: how fast it steps, A/µs.

Then Ztarget = VAC / ΔI, flat up to ftarget = 1 / (π · trise), with trise = ΔI / slew rate. Use for probe fills the probe's target fields; the inputs are remembered for next time.

Solving a rail

Rail, Ground and Solve rail

Below the tabs: Rail lists each VRM and its output net; Ground lists the ticked nets with grounds first, defaulting to the VRM's ground pins' net. Solve rail saves the setup and runs the sweep; problems that stop it are listed in red above. The log shows the field solves as they go.

Tick HTML report next to Solve rail to also write <board>_<rail>_ac_report.html next to the board after each rail's solve; Report opens the shown rail's report. See AC HTML report.

Each rail keeps its last result: switch Rail to look at another rail's curves without solving again. If you change the rail while a solve is running, the result is kept for its own rail and the notes say so.

TargetThe flat level, or the custom mask's range.
VerdictPASS if |Z| is at or below the target everywhere it applies.

Below the table, the notes give the rail's nets and ground, the number of capacitors and series links included, the total plane capacitance, the solve size and time, capacitors left out for having no model, and any warnings. Export CSV… writes |Z|, R and X of every probe at every frequency.

AC HTML report

With HTML report ticked, each rail's solve also writes <board>_<rail>_ac_report.html next to the board, replacing that rail's last one. Like the DC report, it is a single offline file you can email. It holds:

  • a summary and the probe table: pins, minimum and worst |Z|, the target, the margin in dB at the worst point (positive passes), PASS/FAIL, and an overall verdict;
  • an interactive impedance plot, with |Z| above and phase below, and the targets dashed. Drag to zoom, double-click to reset, hover for f, |Z|, R and X. Click a legend entry to hide or show a curve. The grey dotted curves, hidden at first, are each capacitor model on its own (one part, without mounting), useful for matching dips to capacitor banks;
  • a board map seen from the top: the board outline, the rail's copper on every layer merged, the probes as stars and each capacitor colored by its model. Capacitors left out for having no model show as grey crosses;
  • the capacitor models (C, ESL, ESR, self-resonance, how many parts and which), the series links, the sweep, mesh and copper settings, and the solver's size, backend and time;
  • notes: capacitors left out and any warnings.

If the report can't be written, the log says why; the solve's results are kept either way.

Reading an impedance curve
  • Falling at −20 dB/decade (|Z| ∝ 1/f): capacitive. At the low end this is the bulk capacitance; since the VRM is not modeled, the curve keeps rising toward low frequency.
  • Dips: series resonances, where a capacitor bank's C and its ESL plus mounting inductance cancel. The depth is set by ESR.
  • Peaks between dips: anti-resonances, where one bank's inductance resonates with the next bank's capacitance. These are usually where a target fails. Fix them with more or lower-ESL parts, more value overlap between banks, or extra damping (ESR).
  • Rising at +20 dB/decade (|Z| ∝ f): inductive. The capacitors' ESL and their mounting (pad, via and spreading inductance) dominate. Place the cursor here: Info shows it as an equivalent inductance. Shorter, wider connections and more vias lower it.
  • Sharp peaks at high frequency: plane-pair cavity resonances. Their frequencies come from the board's dimensions and stackup.
  • Phase near −90° is capacitive, near +90° inductive, near 0° resistive.

Step-by-step workflows

1. A first DC IR-drop check of one rail
  1. Tick the rail and its ground in the Nets list; untick everything else.
  2. VRMs tab: Add a Source on the regulator's output pins at the set voltage. Add its ground pins.
  3. Loads tab: Add each consumer with its current, tolerance and ground pins.
  4. Solve all. Check the Loads table. For a FAIL, double-click the row, choose Voltage, and click around the load's pins to see where the drop comes from.
  5. Switch to Current density with Arrows to find the bottleneck, change the layout in KiCad, and use Load from KiCad and Solve all again.
2. A full power tree (input → switcher → LDO)
  1. Tick every rail in the chain and the ground.
  2. Add the input as a Source (e.g. the 12 V connector).
  3. Add the switcher as Switcher with its efficiency, output pins (inductor), Input pins on the 12 V net, and ground pins.
  4. Add the LDO as LDO with its quiescent current, dropout and Input pins on the switcher's output.
  5. Add loads on each rail and solve. The VRMs table shows each converter's input current, which includes everything downstream, and its conversion loss.
  6. Set Input min/max and Dropout to catch a regulator starved by upstream drop: its loads show VRM OUT OF REGULATION.
3. A multi-phase regulator
  1. Add the VRM and set phase 1's output pins (its inductor), input pins and ground pins.
  2. Set Phases to the number of phases. Each new phase takes the next parts in sequence (phase 1 on L1 and Q1 gives phase 2 L2 and Q2), or copies the previous phase when there is no next part.
  3. Choose each phase in Edit phase to check its pins, and change any that are wrong.
  4. Set the shared set voltage, type, efficiency and sense pins once.

Each phase carries an equal share of the output current and settles at whatever voltage its copper needs. The VRM regulates its sense pins or, without them, the average of its phase outputs. The VRMs table lists each phase under its VRM: unequal phase voltages show a layout imbalance.

4. Remote sense
  1. On the VRM, set Sense pins to the point the feedback trace connects to (often the load's supply pins).
  2. For differential sensing, also set Ground sense pins on the ground net (the VRM needs ground pins too).
  3. Solve. The sense point sits exactly at the set voltage; pins nearer the VRM read above it (a boost). The tolerance check catches both directions.
5. Solving only part of the board

When some rails are not routed or modeled yet, open the Solve tab and untick their groups. The rest solves, with the substitutions described under Solve tab. Untick the group a Cannot solve message names to get past a setup problem while you fix it.

6. Thermal and current capacity checks
  1. Thermal tab: tick Electro-thermal co-simulation, set ambient and airflow, and limits for maximum temperature and rise.
  2. On the Vias results tab, set a Current limit per via (from your fab's via current rating).
  3. Solve all (electro-thermal). Read the Thermal tab for the hottest point per layer, and sort the Vias tab by current for overloaded vias.
  4. Use the Temperature field to see the map; double-click a Thermal row to jump to its group.
7. Designing decoupling to a target impedance (AC)
  1. Make sure the rail has a VRM (Source is fine), and tick the rail, its ground and any nets joined by series links.
  2. Switch to AC. Capacitors tab: Models from values, then enter ESL and ESR for each model from the datasheets.
  3. Probes tab: add a probe on the device's power and ground pins. Use the calculator for the target, or a custom mask from the device vendor.
  4. Solve rail. In the plot, put the cursor on the worst peak (the table's Worst |Z| tells you where).
  5. Change capacitor models (values, counts by re-assigning parts) or the layout, and solve again. Each probe's margin in dB shows the improvement.
  6. To compare rails, solve each and switch between them with Rail; each keeps its last result for the session.

Capacitors listed under "have no model and were left out" are not part of the result: give them a model or confirm they really do not belong on this rail.

8. Sharing a board and its results
  • Save snapshot… stores the board; anyone with KiPI can open it with Open snapshot… without KiCad or your design files.
  • Keep <board>.kipi-setup.json in version control next to the board.
  • Tick HTML report for a single file you can email: it needs nothing but a browser.
  • Export ▾ → Save results… lets you reopen a long solve later with Open results….

Troubleshooting

The KiPI button does not appear in KiCad

Enable Preferences → Plugins → Enable KiCad API and restart the PCB editor. The first start builds a Python environment and downloads a few hundred MB, which can take several minutes. If the button never appears, right-click the action in Preferences → Plugins and choose Recreate Plugin Environment. On macOS, select a Python 3.10–3.13 interpreter there.

A net is missing from the pin pickers

Pickers only offer nets ticked in the Nets list. Tick it (untick Power & ground only or use the filter to find a signal net).

"No copper path" between a VRM and a load

Usually unrouted copper, an unfilled zone (keep Refill zones on), or a part in series that needs a series link. Show the net in 3D and look for the gap.

The drop is larger than expected

Thermal reliefs, necked traces and too few vias dominate DC drop. Use Current density with Arrows, and the Vias table sorted by current. Compare the 3D copper with KiCad: KiPI only sees filled copper.

NOT CONVERGED

The iterative solver did not reach its tolerance on a very large group. Raise Max edge to shrink the problem, or install the optional PARDISO solver (see the README) for a direct solve of up to 1M unknowns.

Solves are slow

Raise Max edge, analyze fewer nets at once, and untick unneeded groups in the Solve tab. In AC, lower Field solves per decade or raise Min edge. Large planes are cheap; long fine traces are not. PARDISO helps a lot on large boards (Windows and Linux, x86-64).

An AC curve looks wrong
  • Check the notes for capacitors left out for having no model.
  • Check every model's ESL and ESR units (nH and mΩ).
  • Check the probe's ground pins are on the ground being simulated.
  • Remember the VRM is not modeled: the low-frequency rise is expected.
  • Raise Field solves per decade if resonances look jagged.
Reporting a bug

Open an issue at github.com/drewsum/KiPI/issues. Attach the session's .log and .crash.log, the text from About → Copy version info, and if you can, a board snapshot and setup file that show the problem.
